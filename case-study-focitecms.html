Security Architecture Full-Stack Development

LASU FCIT Secure Examination Question Management System (FOCITECMS)

Replacing a vulnerable manual process with a cryptographically secure, multi-tier governance web application for the Lagos State University Faculty of Computing & Information Technology.

Lead Full-Stack Developer
& Security Architect

Tech Stack

Native PHP 8+, MySQL,
Tailwind CSS, Vanilla JS

Client

Lagos State University (LASU)
Faculty of Computing (FCIT)

The Problem

The faculty previously relied on a highly manual process for managing sensitive examination question papers. Physical drives and unprotected digital files were passed between Lecturers, Heads of Departments (HODs), and Examination Officers. This approach presented severe security vulnerabilities, including potential interception, unauthorized modifications (tampering), and premature leakage of exam materials. Furthermore, there was no centralized, immutable audit trail to enforce accountability.

The Solution & Architecture

Cryptographic Blind Lockdown (AES-256-GCM)

The core security mechanism. Once a paper receives final approval, the backend automatically seals the physical file using AES-256-GCM encryption with SHA-256 integrity tags. The file becomes completely immutable and inaccessible—even to database administrators—until the authorized printing window opens.

Dual-Approval Governance & RBAC

I implemented custom dashboards with strictly isolated workflows for Lecturers, HODs, and Examination Officers. The system enforces a strict separation of duties where final approval requires independent, concurrent sign-off from both the HOD and the Exam Officer before a paper is cleared for the crypt-lockdown phase.

Time-Restricted Controlled Printing

To prevent early leaks, server-side enforcement (tied strictly to the Africa/Lagos timezone) ensures that the physical decryption and printing sequence can only be executed exactly one calendar day before the scheduled examination.

Secure Document Conversion & Audit Trails

Uploaded .docx files are sanitized and natively converted into secure PDFs on the backend using LibreOffice headless processes, nullifying localized font or layout tampering. Concurrently, every sensitive action is permanently logged into an immutable database audit trail to ensure absolute institutional accountability.

Technical Challenges Overcome

Implementing AES-256-GCM in Native PHP

One of the major hurdles was ensuring that the encryption mechanism was not just secure, but resilient against tampering. Instead of relying on simpler block ciphers, I utilized PHP's OpenSSL extension to implement Authenticated Encryption with Associated Data (AEAD) via AES-256-GCM. Handling the generation, secure storage, and memory-safe processing of the Initialization Vectors (IVs) and authentication tags natively required meticulous attention to cryptographic best practices, ensuring zero leakage of the plaintext during the encryption pipeline.

Concurrency in Dual-Approval Lockdown

Designing the dual-approval state machine required handling potential race conditions. If an HOD and an Exam Officer approved a document simultaneously, the system had to ensure the crypt-lockdown routine fired exactly once without corrupting the file or the database state. I achieved this by implementing transactional database queries with row-level locking (InnoDB) and strict state-verification checks in the PHP backend before triggering the LibreOffice headless conversion and the subsequent encryption sequence.
