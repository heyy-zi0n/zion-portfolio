Case Study

LASU FCIT Secure Examination Question Management System

I designed and developed a state-of-the-art academic governance and document security web application for the Lagos State University Faculty of Computing & Information Technology (LASU FCIT). The system replaces a vulnerable manual process with a cryptographically secure, multi-tier workflow for drafting, moderating, approving, and printing sensitive examination question papers.

Key Technical Features & Architecture

Multi-Tier RBAC

Custom dashboards and isolated workflows specifically designed for Lecturers, Heads of Departments (HODs), and Examination Officers.

Dual-Approval Governance

A strict separation of duties where final approval requires independent, concurrent sign-off from both the HOD and the Exam Officer before a paper is cleared.

Cryptographic Blind Lockdown

Once a paper receives dual approval, the backend securely seals the physical file using AES-256-GCM encryption with SHA-256 integrity tags. It becomes entirely immutable.

Time-Restricted Printing

Server-side enforcement tied to the Africa/Lagos timezone ensures that physical printing can only be executed exactly one calendar day before the exam.

Secure PDF Conversion

Uploaded .docx files are sanitized and natively converted into PDFs securely on the backend using LibreOffice headless to prevent font or layout tampering.

Immutable Audit Trails

Every sensitive action—logins, uploads, approvals, printing, and overrides—is permanently logged in the database to ensure maximum institutional accountability.

Technical Challenges & Solutions

Implementing AES-256-GCM in Native PHP

The Challenge: Securing exam documents required more than just restricting file paths or hiding URLs. We needed a cryptographic guarantee that once a paper is locked, no internal or external party could read its contents or tamper with it prior to the exact printing window.

The Solution: I built a custom encryption engine utilizing PHP's openssl_encrypt with the AES-256-GCM cipher suite. By leveraging GCM, the system not only encrypts the file but appends an authentication tag to ensure data integrity. The decryption key is handled exclusively in a protected memory segment during runtime, preventing unauthorized decryption even if the database is exposed. Generating a SHA-256 integrity hash before locking provides an immutable fingerprint for the audit trail.

Orchestrating Dual-Approval Lockdown

The Challenge: Academic governance mandated that no single entity could finalize an exam paper. The system had to asynchronously manage states between the HOD and the Exam Officer, gracefully handling rejections, re-submissions, and the critical transition into an encrypted state the moment the second approval was captured.

The Solution: I engineered a deterministic state machine within the MySQL backend. Each exam paper moves through strict enumerated statuses (e.g., draft, pending_hod, pending_officer, locked). Using database transactions, I ensured that when the second approval fires, the application acquires a row-level lock, processes the LibreOffice headless conversion, applies the AES encryption, updates the status, and writes to the audit log simultaneously. If any step fails, the entire transaction rolls back, preventing a corrupted or partially-locked state.
